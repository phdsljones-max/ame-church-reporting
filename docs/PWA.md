# PWA support — AME Monthly Church Reporting

The frontend is an installable web app (PWA). Web-only: no native wrapper, no app-store
submission. Approved by the product owner.

## What was added

| File | Purpose |
|---|---|
| `web/public/manifest.json` | App name, icons, colors (`#5C1A1B` burgundy), `display: standalone` |
| `web/public/icons/` | 4 PNGs generated by `web/tools/generate-icons.py` — 192 & 512 px, plus `-maskable` variants with extra safe-zone padding. Burgundy rounded square, gold ring + gold cross. |
| `web/public/sw.js` | Hand-rolled service worker: precaches the app shell on install; **network-first for `/api/*`** (auth endpoints are never cached); cache-first for same-origin static assets; navigation requests fall back to the cached `index.html` when offline. Cache is versioned (`ame-reports-v1`); old caches are deleted on activate. |
| `web/src/pwa/register.ts` | Registers `/sw.js` — **production builds only**, never in `vite` dev. |
| `web/src/pwa/InstallPrompt.tsx` | Listens for `beforeinstallprompt` and renders an "Install App" button in the site header; hides after `appinstalled`. |
| `web/index.html` | `rel=manifest`, `theme-color` meta, `apple-touch-icon`, `mobile-web-app-capable` metas. |
| Guide page (`#/guide#pwa-install`) | Plain-language install instructions for iPhone and Android. |

## How install works per platform

- **Android / Chrome:** the browser fires `beforeinstallprompt` when the manifest, icons, service
  worker, and HTTPS are all in place → the header shows **Install App** → user accepts → `appinstalled`
  hides the button. Otherwise: browser menu (⋮) → "Install app" / "Add to Home screen".
- **iPhone / Safari:** no install event (so no header button). Steps: open the site in Safari →
  Share → **Add to Home Screen** → Add. The Guide page documents this with screenshots-free numbered steps.
- **Desktop (Chrome/Edge):** address-bar install icon works the same as Android.

## HTTPS requirement

The service worker, manifest, and install prompt all require a **secure context** — `https://` or
`http://localhost`. Serving over plain `http://` on a LAN IP will NOT offer install and will skip
service-worker registration. Deploy behind HTTPS (Netlify, or any TLS-terminating host).

## Testing locally

1. `cd web && npm install && npm run dev` — dev mode, no service worker (expected).
2. Build + preview a production bundle to test the PWA path:
   ```
   npm run build
   npm run preview   # serves dist/ over http://localhost:4173 (secure context ✓)
   ```
3. In Chrome: open DevTools → **Application** → **Manifest** (check icons/name/theme) and
   **Service Workers** (check registered, try "Offline" to see the cached shell). Also verify
   `https://` deployments trigger the header **Install App** button.
4. To regenerate icons: `python3 web/tools/generate-icons.py` (requires Pillow).

## Versioning

Bump `CACHE_VERSION` in `web/public/sw.js` (e.g. `ame-reports-v2`) whenever the app shell changes,
so installed clients pick up the new shell on their next visit.
